## 一、产品定位

### 1.1 核心价值主张

**一句话定位**: 把 AI VTuber 从桌面搬进口袋——随时随地与你的 AI 伙伴对话、互动、陪伴。

| 维度 | 桌面端 | 移动端 |
|------|--------|--------|
| **核心场景** | 直播、游戏、深度创作 | 随身陪伴、碎片化对话、远程监控 |
| **交互方式** | 键鼠 + 大屏 + 桌面宠物 | 触控 + 语音 + 通知推送 |
| **AI 能力** | 本地 GPU 全量推理 | 混合端云架构（轻量端侧 + 云端主力） |
| **角色呈现** | Live2D/VRM 桌面浮窗 | 2D 头像 + 表情动画 + 语音优先 |
| **网络依赖** | 可完全离线 | 在线为主，离线基础对话 |

### 1.2 移动端差异化

1. **语音优先交互**：移动端天然适合语音，ASR/TTS 是核心体验而非附加功能
2. **通知驱动陪伴**：利用推送通知实现主动问候、记忆提醒、定时日记
3. **跨设备连续性**：与桌面端共享记忆系统和角色配置，无缝切换场景
4. **直播遥控器**：移动端作为桌面直播的远程控制面板，实时监控弹幕和状态
5. **口袋里的角色**：快速查看角色状态、情感状态、记忆摘要

### 1.3 目标用户画像

| 用户类型 | 特征 | 核心需求 | 优先级 |
|----------|------|----------|:------:|
| **VTuber 爱好者** | 18-30 岁，活跃于 B 站/抖音 | 随时与 AI 角色互动，直播时移动端辅助 | P0 |
| **AI 陪伴用户** | 20-35 岁，追求情感陪伴 | 全天候 AI 对话伙伴，个性化角色 | P0 |
| **桌面端老用户** | 已有桌面端使用经验 | 移动端延伸，跨设备同步 | P1 |
| **轻量用户** | 不愿搭建桌面环境 | 通过手机快速体验 AI VTuber | P1 |
| **直播创作者** | VTuber/主播 | 移动端监控直播状态，远程互动 | P2 |

## 二、用户故事

### US-1: 日常陪伴对话

> 作为一名 AI 陪伴用户，我希望在通勤、午休、睡前等碎片时间通过手机与我的 AI 角色聊天，让它记住我的喜好和心情，感受到持续的陪伴。

**验收标准**:
- 打开 App 即可开始对话，首次响应 < 3 秒
- 角色能回忆起之前的对话内容（记忆系统）
- 支持文字和语音两种输入方式
- 对话历史可在手机端和桌面端同步查看

### US-2: 语音互动

> 作为一名 VTuber 爱好者，我希望用语音直接和 AI 角色对话，就像打电话一样自然，AI 用角色的声音回复我。

**验收标准**:
- 长按按钮录音，松开发送语音消息
- 语音自动转文字显示在对话中
- AI 回复同时生成文字和语音
- 语音播放时角色头像有表情/动画反馈

### US-3: 直播远程监控

> 作为一名直播创作者，我希望在户外或不在电脑前时，通过手机查看直播间状态、弹幕，并让 AI 角色自动回复弹幕互动。

**验收标准**:
- 实时显示直播平台连接状态和弹幕流
- 可手动/自动切换 AI 回复模式
- 收到特殊弹幕（如礼物、SC）时推送通知
- 可远程调整 AI 角色的回复风格和活跃度

### US-4: 角色切换与个性化

> 作为一名多角色用户，我希望在手机上快速切换不同 AI 角色，每个角色有独立的性格、记忆和声音。

**验收标准**:
- 角色列表展示头像、名称、简介和个性标签
- 一键切换角色，切换后对话上下文自动切换
- 每个角色有独立的对话历史和记忆
- 支持从桌面端同步自定义角色

### US-5: 跨设备无缝衔接

> 作为一名桌面端老用户，我希望在手机上继续桌面端未完成的对话，AI 记得之前聊过的内容，不需要重新介绍自己。

**验收标准**:
- 登录同一账号后自动同步记忆系统（四层架构）
- 对话历史跨设备可查
- 角色配置（性格、声音、外观）自动同步
- 设备间切换时提供"上次对话"快捷入口

## 四、技术约束与架构决策

### 4.1 端侧推理 vs 云端推理

| 维度 | 端侧推理 | 云端推理 |
|------|----------|----------|
| **延迟** | 首 token 快（无网络开销） | 受网络影响，通常 200-500ms |
| **能力上限** | Sub-1B 模型，12-15 tok/s（骁龙8 Elite） | 无限制，GPT-4o 级别 |
| **功耗** | 高（NPU 持续工作） | 低（仅网络通信） |
| **成本** | 一次性（设备算力） | 持续性（API 费用） |
| **离线** | 支持 | 不支持 |
| **隐私** | 数据不出设备 | 数据上传云端 |

**决策**: MVP 采用纯云端架构（连接桌面端后端），V1 引入混合架构（端侧处理简单意图识别和离线问候，云端处理复杂对话），V2 探索端侧完整推理。

**混合架构设计**:
```
用户输入 → 端侧意图分类器
  ├─ 简单意图（问候/确认/闲聊）→ 端侧 Sub-1B 模型
  ├─ 复杂意图（知识问答/创作/角色扮演）→ 云端 LLM
  └─ 离线状态 → 端侧模型 + 预设回复缓存
```

### 4.2 React Native 能力边界

| 能力 | RN 支持度 | 方案 |
|------|:---------:|------|
| **基础 UI** | 原生支持 | React Navigation + 原生组件 |
| **动画** | 良好 | react-native-reanimated (已有依赖) |
| **音频录制** | 需原生模块 | react-native-audio-api 或 expo-av |
| **音频播放** | 需原生模块 | react-native-track-player |
| **Live2D 渲染** | 需桥接 | WebView + Canvas 或 Skia (react-native-skia) |
| **VRM/3D** | 需桥接 | WebView + three.js 或 expo-gl |
| **推送通知** | 原生支持 | @react-native-firebase/messaging |
| **本地存储** | 原生支持 | AsyncStorage (已有) + SQLite (react-native-sqlite-storage) |
| **WebSocket** | 原生支持 | react-native-websocket (已有依赖) |
| **端侧 AI** | 需桥接 | react-native-executorch 或 ONNX Runtime RN binding |

**关键约束**:
- Live2D/VRM 渲染在移动端性能受限，MVP 不包含，通过 2D 头像 + Lottie 动画替代
- 端侧推理需原生桥接，工作量大，推迟到 V2
- 音频处理需平台特定原生模块，但社区方案成熟

### 4.3 移动端特有 UX 挑战

#### 小屏幕适配
- 对话页面：最大化消息展示区域，输入栏底部固定
- 角色选择：卡片式横向滑动，非桌面端的列表布局
- 设置页面：分组折叠式，避免长列表
- 直播监控：信息密度优先，弹幕流式滚动

#### 功耗管理
- 后台保活策略：仅维持 WebSocket 心跳，不进行 AI 推理
- 推送通知替代轮询：利用 FCM/APNs 而非客户端定时请求
- 按需加载：角色模型、记忆数据懒加载
- 音频播放优化：使用系统级音频会话管理

#### 网络不稳定处理
- 消息队列：离线时消息本地缓存，恢复网络后自动发送
- 重试机制：指数退避 + 最大重试次数
- 降级策略：云端不可用时切换端侧模型或预设回复
- 状态提示：清晰展示连接状态（在线/离线/重连中）

## 五、竞品对标

### 5.1 竞品矩阵

| 维度 | ChatGPT App | Gemini App | Character.AI App | **咕咕嘎嘎 Mobile** |
|------|-------------|------------|-------------------|---------------------|
| **定位** | 通用 AI 助手 | Google AI 生态入口 | AI 角色社交 | AI VTuber 陪伴 + 直播 |
| **角色系统** | 无（单一人设） | 无 | 丰富（UGC 角色） | 丰富（可定制 + 桌面端同步） |

| **视觉呈现** | 纯文字 + 图片 | 纯文字 + 图片 | 2D 头像 + 文字 | 2D 头像 + 表情动画 |
| **记忆系统** | 基础记忆 | 有限 | 角色内记忆 | 四层记忆架构 |

### 5.2 差异化优势

1. **唯一的 AI VTuber 移动端方案**：市场无直接竞品，ChatGPT/Character.AI 非 VTuber 场景
2. **桌面 + 移动联动**：直播遥控、记忆同步、角色共享，形成闭环
3. **声音克隆能力**：GPT-SoVITS 支持个性化声音（桌面端训练，移动端使用）
4. **开源可定制**：用户可自行部署后端，完全掌控数据
5. **多 LLM 灵活切换**：不绑定单一模型供应商，用户可按需选择

### 5.3 竞争劣势与应对

| 劣势 | 应对策略 |
|------|----------|
| 品牌知名度低 | 开源社区推广 + VTuber 圈子精准营销 |
| 无端侧推理（MVP） | 优先保证云端体验流畅，V2 补齐 |
| 需自建后端 | 提供 Docker 一键部署 + 云服务版本 |
| 角色渲染能力弱（MVP） | 语音优先策略，用声音弥补视觉 |

## 九、风险与缓解

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|:----:|----------|
| React Native 原生模块兼容性 | 语音/音频功能受阻 | 中 | 提前验证关键原生模块，备选 WebView 方案 |
| 桌面端 API 不稳定 | 移动端体验连带受损 | 中 | API 版本化、移动端增加容错和降级 |
| 应用商店审核 | 上架延迟 | 低 | 提前准备隐私政策、内容分级，预留审核缓冲期 |
| 端侧推理性能不达标 | V2 功能推迟 | 高 | 先用云端方案兜底，端侧作为增强而非必需 |
| 用户预期管理 | 与桌面端功能差距大导致不满 | 中 | 明确移动端定位，引导页说明差异化场景 |
