# PRD: 主题系统增强

## 1. 项目信息

| 字段 | 值 |
|------|------|
| Language | 中文 |
| Programming Language | PySide6 + qfluentwidgets (Python) |
| Project Name | `ai-vtuber-theme-enhancement` |
| 原始需求 | 为 AI VTuber 桌面应用增加多主题支持，除深色/浅色外增加彩色主题，改善浅色主题适配，增加主题预览和动态效果 |

**原始需求复述**：
用户希望应用不再局限于深色/浅色两套主题，要增加多种不同颜色的主题方案（非单一颜色），考虑不同动画效果，并参考其他软件的主题设计。深色主题已适配良好，浅色主题适配需改善。

---

## 2. 产品定义

### Product Goals

1. **主题多样性**：提供 ≥8 套预设主题（含彩色主题），超越深色/浅色二元选择，让用户能表达个性
2. **浅色主题完善**：消除浅色主题下的视觉缺陷（对比度不足、硬编码暗色值、组件不跟随），达到与深色主题同等的完成度
3. **主题体验闭环**：用户可以在设置中预览、一键切换、持久化主题偏好，主题切换过程流畅无闪烁

### User Stories

| # | 用户故事 | 验收标准 |
|---|---------|---------|
| US1 | 作为日常用户，我想选择不同颜色风格的主题（如薰衣草紫、海洋蓝、樱花粉），让应用更有个性 | 切换主题后全应用颜色一致变化，无残留暗色/硬编码色值 |
| US2 | 作为浅色模式用户，我想获得与深色模式同等质量的视觉体验 | 浅色模式下所有页面（设置/对话/训练/下载）文字清晰可读、对比度 ≥4.5:1 |
| US3 | 作为新用户，我想在设置页预览不同主题效果后再决定选用 | 主题选择器展示色卡预览，hover/点击可实时预览 |
| US4 | 作为老用户，我切换主题后重新打开应用，主题偏好被保留 | 主题选择持久化到本地，重启后自动恢复 |
| US5 | 作为视觉敏感用户，我想要动态渐变和微动画效果让界面更生动 | 选中主题后按钮/进度条/卡片有对应的渐变和过渡动画 |

#### 主题方案定义格式

```python
# themes/ocean_dark.py
from gugu_native.theme import ThemeDefinition

OCEAN_DARK = ThemeDefinition(
    name="ocean_dark",
    display_name="海洋",
    mode="dark",                    # 基底模式: dark / light
    accent="#0ea5e9",               # 强调色 — 海洋蓝
    accent_hover="#0284c7",
    accent_pressed="#0369a1",
    window_bg="#0c1222",            # 深海蓝黑
    sidebar_bg="#0a0f1e",
    card_bg="#132038",              # 深海卡片
    # ... 其余 60+ 颜色自动从基底 + accent 衍生
)
```

#### 颜色衍生规则

| 语义色 | 衍生规则 | 示例（Ocean Dark） |
|--------|---------|-------------------|
| accent | 用户选择 / 主题定义 | `#0ea5e9` |
| accent_hover | accent 亮度 -8% | `#0284c7` |
| accent_pressed | accent 亮度 -16% | `#0369a1` |
| user_bubble_bg | = accent | `#0ea5e9` |
| user_bubble_border | accent 亮度 +15% | `#38bdf8` |
| progress_start | = accent | `#0ea5e9` |
| progress_end | accent 色相 +30° | `#6366f1` |
| card_bg (dark) | accent 饱和度 -60%, 亮度 15% | `#132038` |
| card_bg (light) | accent 饱和度 -80%, 亮度 97% | `#f0f9ff` |

### 待确认问题（Open Questions）

| # | 问题 | 影响 | 建议 |
|---|------|------|------|
| Q1 | **主题文件存储格式**：每主题一个 `.py` 文件 vs 一个 `themes.json` 统一文件？ | 开发体验 & 可扩展性 | 建议：每主题一个 `.py` dataclass 文件放 `themes/` 目录，便于 git diff 和社区贡献 |
| Q2 | **彩色主题的深浅模式**：彩色主题是否自动生成深/浅两套变体，还是每个主题固定深或浅？ | 主题数量 & 复杂度 | 建议：彩色主题固定基底（dark/light），不做深浅翻转；用户可额外叠加强调色微调 |
| Q3 | **`qfluentwidgets` 主题色范围**：`setThemeColor()` 自动衍生 7 个变体，是否足够覆盖 `AppColors` 中 accent 系列的 8 个字段？ | 是否需要手写衍生算法 | 需验证：若不足，需在 `ThemeDefinition` 中手写 `derive_colors(accent)` 函数 |
| Q4 | **动画性能底线**：呼吸灯/渐变动画在低端 GPU 机器上是否需要自动降级？ | P2 动画效果的用户覆盖面 | 建议：P2 动画默认开启，在 perf_manager 检测到低帧率时自动降级 |
| Q5 | **现有硬编码颜色的清理范围**：`settings_page.py` 中按钮渐变色硬编码约 20+ 处，是否在 P0 阶段全部清理？ | P0 工作量 | 建议：P0 必须全部清理，否则新主题在这些按钮上会暴露蓝色残留 |
| Q6 | **主题切换动画**：是否实现淡入淡出过渡（如 200ms opacity 动画）？ | 体验感 vs 实现复杂度 | PySide6 整体 opacity 动画困难，建议先做即时切换 + P2 再探索 |
